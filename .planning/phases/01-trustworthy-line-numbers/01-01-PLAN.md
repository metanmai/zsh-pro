<objective>
Fix LINE-01: the off-by-one total line count. `core/analyze/analyzer.go:28` currently computes `Lines: strings.Count(string(src), "\n") + 1`, which reports 1 for an empty file and over-counts any file that ends in a trailing newline. Replace it (per locked decision D-03) with an editor-style helper: an empty file is 0 lines; otherwise count newlines and add 1 only when the final byte is not a newline. Update the one existing test (`TestAnalyzeBucketsCategoriesAndFlagsSecrets`, the assertion at `analyze_test.go:151`) that currently asserts the buggy value.

Purpose: Guarantee `Analysis.Lines` is the true line count and is always >= every issue's statement line — the foundation for the per-issue line trust in plan 01-02 and the total-Lines pin in 01-03.
Output: Corrected `countLines` helper in `analyzer.go`; updated assertion in `analyze_test.go`; `go test ./core/analyze/...` green.
