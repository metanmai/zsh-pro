<objective>
Fix LINE-02: per-issue line mis-attribution. In `core/shell/zsh/parse.go`, the comment-pull-up loop (`:36-41`) currently overwrites BOTH the `start` byte offset AND `startLine` when it finds a leading `#` comment, so `Block.StartLine` ends up being the comment's line. Per locked decisions D-01 and D-02, delete only the `startLine = c.Pos().Line()` assignment at line 39 (keep the `start = c.Pos().Offset()` update so `Block.Text` still includes the comment as context). `startLine` then stays at its initialization (`stmt.Pos().Line()` at line 33) — the statement's own line. The four `reconciler.go` readers inherit the fix for free; no `Block` field is added and the reconciler is NOT touched. Update the one test (`TestParseClassifiesKinds`, assertion at `parse_test.go:54-55`) that documents the buggy value.

Purpose: Satisfy LINE-02 with the zero-churn approach the user locked — issues report the statement line, not the comment line.
Output: One line deleted + one comment updated in `parse.go`; one assertion changed (`want 1` -> `want 2`) in `parse_test.go`; the zsh and analyze packages stay green.
</objective>
