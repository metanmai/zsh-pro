<objective>
Close the durable domain/persistence half of CR-05 with a pre-mutation operation journal, canonical semantic receipts, exact Git-ref/state recovery, and execute-once replay.

Purpose: A process can disappear after creating a branch ref or replacing canonical state. Recovery must identify those external effects without trusting a durability value that was serialized before the effect occurred.
Output: Descriptor-bound journal lifecycle, semantic mutation receipts/results, typed Git-ref outcome, authenticated reopen recovery, and a deterministic cross-resource fault matrix.
</objective>

<interfaces>
Current contracts and required extensions:

- `core/worktree/atomic_unix.go::StateStore.WithTransaction(ctx, func(*State) error) error` holds the authenticated descriptor-relative lock, marshals before `replaceCanonical`, and cannot expose whether rename/directory-sync happened after an error. `stateStoreFaults` already has write, fileSync, rename, dirSync, beforeRename, afterRename, and afterDirSync seams.
- `replaceCanonical` writes and fsyncs a same-directory temporary, renames it over `worktree.json`, then syncs the retained root descriptor. The new API must report observed stages outside the serialized state bytes; it must not write a terminal durability status into the candidate JSON.
- The existing fixed `recovered-persistence` marker proves the required no-follow, mode-0600, owner, inode-rebind, file-sync, unlink, and directory-sync mechanics. The mutation journal is a separate fixed object with a different protocol and lifecycle; it must not overload that forensic marker.
- `core/worktree/state.go::OperationReceipt` is shell/operation/request-fingerprint bound and capped at 64 receipts per shell. Extend its tagged union with a mutation semantic receipt containing verb and exact resulting revision, but derive `Committed` and `RecoveryRequired` from post-I/O evidence.
- `core/worktree/service.go::Checkout` currently calls `Repository.CreateFrom` for `checkout -b` before `replaceWorkflowGeneration`; `ResetHard` only replaces state. Add credential-bearing domain requests for execute and recovery while retaining the direct public workflow methods as adapters.
- `core/store/store.go::CreateFrom` uses `updateRefCAS` from an all-zero old OID. Add a typed mutation variant that exposes success/uncertainty and requires exact direct-ref readback; preserve `CreateFrom` behavior for ordinary `branch <name>`.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| authenticated shell request -> operation journal | A bearer capability authorizes one value-free request descriptor without being persisted. |
| operation journal -> Git ref | The fixed journal must be durable before checkout -b can create a ref. |
| Git ref -> canonical worktree state | Two crash-consistency domains must converge without compensating or repeating an observed mutation. |
| canonical state -> journal clear | Semantic receipt/state and exact ref proof must be durable before recovery authority is removed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-07-18-01 | Spoofing | mutation journal | critical | mitigate | Descriptor/root/lock/inode authentication, canonical authority/operation/request binding, constant-time runtime credential verification, and uniform rejection before disclosure. |
| T-07-18-02 | Tampering | fixed journal file | critical | mitigate | Descriptor-relative no-follow opens, mode/owner/regular-file validation, inode rebinding checks, strict bounded protocol, and no overwrite of an existing journal. |
| T-07-18-03 | Repudiation | state durability truth | critical | mitigate | Terminal durability is derived from observed rename/sync/ref/journal milestones and reopen evidence, never predicted inside pre-rename bytes. |
| T-07-18-04 | Tampering | checkout -b ref/state split | critical | mitigate | Journal-before-CAS, exact direct-ref readback, canonical semantic receipt, one lock, and cross-resource fault/reopen matrix. |
| T-07-18-05 | Elevation of Privilege | recovery request | critical | mitigate | Same shell capability, operation ID, request fingerprint, journal MAC, and descriptor root are required; foreign requests cannot clear or continue the journal. |
| T-07-18-06 | Denial of Service | replay/competing operation | high | mitigate | One fixed bounded journal, receipt caps, identical replay, explicit recovery-required for a competing descriptor, and no unbounded journal accumulation. |
| T-07-18-07 | Information Disclosure | journal/receipt/error | high | mitigate | Persist only identifiers, hashes, and exact OIDs/revision; canary tests prohibit branch/source/path/live values/raw capability/token/diagnostics. |
| T-07-18-08 | Tampering | journal clear | high | mitigate | Inode-bound unlink plus root-directory fsync occurs only after exact ref and canonical rename/directory-sync proof. |
| T-07-18-09 | Repudiation | lost response | high | mitigate | Canonical receipt without a journal proves completion; matching replay returns the exact revision with zero mutation calls. |
| T-07-18-10 | Tampering | recovered-persistence marker | high | mitigate | Keep forensic marker protocol and mutation journal separate; regression tests prove neither lifecycle clears or authenticates the other. |
</threat_model>
