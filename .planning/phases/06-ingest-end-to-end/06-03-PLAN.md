</objective>

Contracts to extend without bypassing:
- `runInstallWithStoreInitialization` is the shipped install composition point. Its store initializer must complete before cache preparation; its promotion order remains loader then `.zshrc`.
- `preparedWrite` currently stages and promotes by path. Replace its mutation internals with the authenticated transaction protocol; do not create an ingest-only overwrite writer.
- `StoreInitialization` is the CLI-neutral initializer result. It maps the exact injected store's root/ownership/rollback operations without importing `core/store`.
- 06-01 provides model-owned `IngestBaseline`, `IngestCommitOutcome`, and `IngestAbortOutcome`; 06-02 implements CommitIngest in parallel, and `IngestBaseline.ProfileObjectPresent` is the durable adoption discriminator.
- Go 1.25 `os.OpenRoot`, `os.Root.Rename`, `os.Root.Link`, `os.Root.Lstat`, and rooted open/remove calls provide descriptor-relative namespace operations with no new dependency.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| Requested `.zshrc` path -> resolved target descriptor | Symlinks and parent pathnames can change after validation. |
| Validated target -> move-aside/candidate namespace operations | A concurrent writer can replace, recreate, or mutate the target. |
| Process memory -> filesystem durability | Successful syscalls are not durable until file and directory metadata are synced. |
| Recovery journal -> next invocation | Stale or attacker-created artifacts must not become arbitrary path operations. |

## ASVS Level 1 Baseline

OWASP ASVS Level 1 applies. V5.1 validation maps to marker/journal/basename checks; V12.3 file execution/storage maps to authenticated roots, regular-file checks, exclusive links, and fail-closed recovery; V7.4 error handling maps to stable classified outcomes. Execution is blocked while any critical/high threat lacks the named automated test.
