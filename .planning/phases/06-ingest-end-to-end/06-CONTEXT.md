## Phase Boundary

Wire the already-built Phase 2/3 pieces into a single, real-file on-ramp: `zsh-pro` ingests a real `~/.zshrc` end-to-end — parse → classify → `ir.Build` → (`ir.Regenerate`) → `Store.Commit(main)` — capturing declarative state, routing imperative run-once lines to the unmanaged master block (never silently dropped), excluding detected secrets by default with an explicit withheld report, keeping re-ingest idempotent, detecting installer appends that landed outside the managed BEGIN/END block, and round-tripping the committed baseline back to a behavior-equivalent `.zshrc` (the Phase 2 oracle held end-to-end against a real file). Five deliverables, all HOW-level — WHAT/WHY are locked in `06-SPEC.md` (5 requirements) and inherited from Phase 2 (IR + round-trip oracle), Phase 3 (`Store.Commit` + `WithheldReport` + secret exclusion), and the Phase 5 SPEC boundary (Phase 5 owns the installer + marker contract; Phase 6 owns ingest + out-of-block detection):

1. **End-to-end ingest orchestration + `ingest` CLI verb** — a new entry point reads `~/.zshrc` (default `~/.zshrc`, overridable by an explicit path arg), calls `provider.Parse` → `ir.Build`, and commits the resulting `model.Profile` to the `main` baseline via the injected `Store.Commit`. A new `ingest` verb (OQ-06-01) dispatches it from `CLI.Run`'s `switch args[0]`, mirroring the existing `analyze` case.
2. **Imperative → master-block content routing** — every `EffectiveManaged() == false` entry's verbatim `Text` is routed into the unmanaged master-block region of `~/.zshrc` (reusing the Phase 5 installer's master-block/marker contract, D-12), rather than the templated declarative store. Every source statement is accounted for — committed as a managed entry OR routed to the master block; none dropped.
3. **WithheldReport surfacing** — the report `Store.Commit` already returns is surfaced to the user on ingest (Phase 3 built the producer; Phase 5/6 is the consumer), naming exactly what was withheld; already-dynamic secrets commit verbatim and are not reported.
4. **Out-of-block installer-append detection + warning** — on ingest, scan `~/.zshrc` for content appended AFTER the managed BEGIN/END block by a later installer (e.g. `# added by nvm`), surface a read-only warning, and leave that content byte-identical (never clobber/reorder). Built on Phase 5's marker contract (D-12: Phase 5 guarantees non-destruction; Phase 6 owns the detection/warning).
5. **End-to-end round-trip oracle** — after ingest commits `main`, `Store.Read(main)` → `ir.Regenerate` reproduces a behavior-equivalent `.zshrc`, exercising the Phase 2 round-trip oracle against a real-shaped ingested fixture (the ING-01 regression pin, now end-to-end).

**In scope:** the ingest orchestration flow; the `ingest` verb + its path arg / `--json` flag; imperative→master-block routing against the Phase 5 marker/region contract (reconciled at plan time); WithheldReport rendering (human + `--json`); the out-of-block-append read-only detector/warning; the end-to-end round-trip test against a real-shaped fixture; composition-root wiring of the store into the CLI for the ingest verb at `core/cmd/zsh-pro/main.go`.

**Not in scope (later/other phases or reused verbatim):** the BEGIN/END block writer/installer itself (marker sentinels, byte-exact idempotent rewrite, master-block preservation mechanism) — Phase 5 (BOOT-01), consumed here, NOT re-implemented; IR / partial-eval / classifier / regenerator internals — Phase 2 (reused verbatim; Phase 6 does not modify `core/ir` or `core/shell/zsh` parse/classify/regen beyond wiring); store internals (git driver, serialization, secret-exclusion mechanism, keychain/vault) — Phase 3 (reused verbatim); runtime deref-on-switch of `SecretRef` at apply time — Phase 4/5 activation path (Phase 6 only excludes-and-reports at ingest time); multi-file config graphs / sourced fragments — out for the whole milestone; filesystem / live-`$HOME` / `$(...)` resolution — dynamic values stay late-bound verbatim (EVAL-01), no execution of user config (static AST inspection only); other shells (bash/fish); auto-activate on `cd`, remote sharing/trust — future.

## Implementation Decisions

### Area 1 — `ingest` verb: interface, arguments, output

- **D-01: The verb is `ingest`; invocation `zsh-pro ingest [path] [--json]`, default path `~/.zshrc`** (OQ-06-01, applied). Milestone vocabulary is consistent on "ingest" (ROADMAP/REQUIREMENTS/CLAUDE.md: "ingest component/engine/on-ramp"); `init` is rejected (overloads `Store.Init` + installer bootstrap), `import`/`adopt` are non-canonical. The positional path + `--json` flag parsing mirrors `runAnalyze` exactly (`core/cli/cli.go:49-63`): default `~/.zshrc`, one bare positional overrides the path, `--json` toggles structured output, an unknown `-flag` is `ExitUsageErr`. `util.ExpandHome` is used ONLY at the CLI boundary to resolve the READ path (as `runAnalyze` does at line 63) — never inside the IR/store path (EVAL-01 / SPEC constraint).
- **D-02: The verb dispatches from `CLI.Run`'s `switch args[0]`, adding `case "ingest"`, mirroring the `analyze` case** (`core/cli/cli.go:37-46`). It reuses the typed `model.ExitCode` contract (0 clean / 1 runtime / 2 usage / 3 actionable) and the `fail` helper (structured JSON error to stdout in `--json`, human line to stderr — `core/cli/cli.go:88-100`), so the agent contract (exactly one JSON object on stdout in `--json` mode, on success OR failure) holds for `ingest` as it does for `analyze`.
- **D-03: Human-mode ingest output is a concise, deterministic summary; the load-bearing accounting is a line-count reconciliation.** It reports: profile committed to `main`, count of managed (declarative) entries, count/lines routed to the master block, the WithheldReport (D-08), and any out-of-block-append warning (D-11). The SPEC's zero-dropped invariant (`managed_entries + master_block_lines` accounts for every non-blank, non-comment source statement) is computed and surfaced, so a silently-dropped line is visible in the summary AND falsifiable by test. Exact wording/field labels are Claude's discretion (see Discretion), provided the counts and the withheld/warning surfaces are present.
- **D-04: `--json` mode emits one structured envelope** (managed count, master-block line count, withheld list, out-of-block warning list, ok/exit_code) mirroring the existing render envelope pattern (`core/render/json.go` + `core/dto`) and the `fail` envelope shape. Whether ingest gets a dedicated DTO/renderer in `core/render`+`core/dto` or a smaller inline JSON struct is Claude's discretion (OQ-06-03 — safe default: a small ingest-result DTO in `core/dto` rendered via a thin `core/render` path, consistent with the existing domain→DTO separation; do NOT put zsh text or store types on the wire).

### Area 2 — Imperative → master-block routing (against the Phase 5 marker contract)

- **D-05: The routing SPLIT is already computed by the IR — Phase 6 consumes `EffectiveManaged()`, it does not re-classify.** For each `model.Entry` in the built `Profile`: `EffectiveManaged() == true` → the entry is committed to the store as a managed declarative entry (via `Store.Commit`, which regenerates the declarative subset); `EffectiveManaged() == false` → the entry's verbatim `Text` is routed to the master block. This is the EXACT same predicate `ir.Regenerate` gates on (`core/ir/regen.go:26`), so the store view and the master-block view partition the source with no overlap and no gap. Phase 6 adds NO new classification logic (precision-over-recall gate stays in `core/ir/route.go`, untouched).
- **D-06: The master block is a distinct, installer-preserved region of `~/.zshrc` holding imperative verbatim `Text` — NOT a second committed file in the git store** (OQ-06-02, applied). Imperative run-once code is unmanaged/non-switchable, so it does not belong in the switchable per-category store; it lives in the `.zshrc` region Phase 5's installer (D-12) preserves byte-for-byte. Rejected alternatives: (a) a separate committed store file (imperative code is not switchable state); (b) a single combined BEGIN/END block mixing managed + master content (breaks the managed block's byte-identical idempotency — the managed block is tool-owned/regenerated, the master block is user-owned).
- **D-07: The imperative→master-block WIRING is a PLAN-TIME RECONCILIATION GATE against Phase 5's ACTUAL landed installer, mirroring how Phase 5 reconciled against Phase 4's `emit.go`.** Phase 5 is planned but NOT yet executed on disk (grep confirms no `>>> zsh-pro` markers / no installer in `core/`), so the exact region layout Phase 6 writes into is a forward reference. The BEHAVIOR is locked (imperative verbatim, never dropped; managed block byte-identical; out-of-block content preserved) independent of the physical seam. Phase 5's CONTEXT locks the contract Phase 6 reconciles against: markers `# >>> zsh-pro >>>` (BEGIN) / `# <<< zsh-pro <<<` (END) (Phase 5 D-09); find-BEGIN..END-then-replace, everything outside preserved byte-for-byte (Phase 5 D-10); the master block is the user's own `.zshrc` content OUTSIDE the markers that D-10 preserves by construction (Phase 5 D-12). The plan's FIRST task diffs Phase 6's routing target against Phase 5's actual installer API once it lands and wires to exactly that — Phase 6 REUSES the installer, it does not re-implement a block writer (SPEC constraint). If Phase 5 has not landed when Phase 6 plans, the plan treats the Phase 5 D-09/D-10/D-12 contract as the reconciliation baseline and flags the seam as a plan gate.

### Area 3 — WithheldReport surfacing (secret exclusion, ingest-side)

- **D-08: Ingest surfaces the `WithheldReport` `Store.Commit` already returns — Phase 6 is the CONSUMER of a producer Phase 3 already built.** `Store.Commit` runs `excludeSecrets` and returns `(WithheldReport, error)` (`core/store/store.go:211-303`); ingest reuses that end-to-end (no new regex, no new AST, no new exclusion logic — SPEC constraint). Human mode prints each `WithheldSecret{Name, StartLine}` as a plain line ("withheld: API_TOKEN (line 12)"); `--json` mode includes the list in the envelope (D-04). NO secret VALUE is ever printed (only name + line — the `WithheldReport` shape carries no value, and Phase 3's `excludeSecrets` never logs the literal). Already-dynamic secrets (`export TOKEN=$(op read ...)`) commit verbatim and are NOT in the report (Phase 3 D-08), so they are not surfaced — matching SPEC Requirement 2's acceptance.
- **D-09: A `Store.Commit` error is surfaced as a runtime error via `fail`, never a partial/leaky success.** Phase 3's `excludeSecrets` fails CLOSED on an unsafe secret shape (`ErrUnsafeSecretShape`) or an unavailable backend (`ErrSecretBackendUnavailable`) and aborts before any ref moves; ingest propagates that error to `fail` (exit 1, zsh-pro-phrased). Ingest never falls through to a verbatim/leaky commit on a secret-handling error — it reuses Phase 3's fail-closed guarantee unchanged.
- **D-10: The `main` baseline is committed via `Store.Commit(ctx, "main", profile, msg)`; `Store.Init` is ensured idempotently first.** Ingest calls `Store.Init` (idempotent no-op on an existing store, Phase 3 D-06) before `Commit`, so a first-run ingest bootstraps the bare repo + `main` baseline and a re-ingest reuses it. The commit message is fixed/deterministic zsh-pro text (commit timestamp is already pinned by the store's `commitTS`, `core/store/store.go:31`, so the baseline stays byte-reproducible). Re-ingesting updates `main` (a new commit on the same branch — the store parents on the branch tip, `core/store/store.go:257-265`); it does not duplicate committed entries (the tree is rewritten from the fresh profile each time).

### Area 4 — Out-of-block installer-append detection + warning

- **D-11: Out-of-block detection is READ-ONLY surfacing built on the Phase 5 marker contract — it detects, warns, and leaves the appended content byte-identical.** On ingest/install, scan `~/.zshrc`: locate the managed BEGIN..END region (Phase 5 markers, D-07 reconciliation), and if non-blank content exists AFTER the END marker, emit a warning identifying that lines exist outside the managed markers that may need manual attention. The content is left in place — never clobbered, moved, or reordered (Phase 5's installer already preserves everything outside `[BEGIN, END]` by construction, D-12; Phase 6 only READS to warn). Ingest exits WITHOUT error in this case (a warning, not a failure — SPEC Requirement 4 acceptance: "exits without error").
- **D-12: The scan is a simple line/marker string search, not a re-parse.** Detection keys off the literal BEGIN/END marker strings (grep-style: find END marker, check for subsequent non-blank/non-comment lines), reusing the marker constants Phase 5 defines in `core/shell/zsh` — Phase 6 does not re-derive the marker text (single source of truth in the installer package, reached via the composition root / a provider seam if the marker must cross a package boundary; Claude's discretion on the exact seam, OQ-06-04). NO AST parse of the out-of-block content is needed — the requirement is only to DETECT-and-warn that foreign content exists, not to classify or ingest it. Whether the detector lives in the same package as the installer (natural home, has the markers) or in the ingest orchestration reading a marker constant is Claude's discretion (safe default: co-locate with the Phase 5 installer, which already owns the marker sentinels + the read-modify-write of `~/.zshrc`).

### Area 5 — Round-trip oracle fixture + composition-root wiring

- **D-13: The end-to-end round-trip test ingests a representative real-shaped `~/.zshrc` fixture and asserts the Phase 2 oracle holds.** After ingest commits `main`, `Store.Read(main)` → `ir.Regenerate` → the Phase 2 round-trip oracle (`core/ir/roundtrip_test.go` / the `zsh -f` execute-and-diff instrument, Phase 2 D-08): regenerated output parses to a `model.Profile` structurally equal to the committed one; verbatim/imperative statements byte-identical to source; templated declarative slices behavior-equivalent. This is the ING-01 regression pin, now exercised end-to-end against a real file rather than only synthetic IR fixtures.
- **D-14: The fixture is a hand-authored, deterministic, real-shaped `~/.zshrc` covering every routing/secret/idempotency/out-of-block path in ONE file** (or a small family of focused fixtures — Claude's discretion). It MUST contain: declarative entries (alias / export / PATH), a dynamic-but-declarative value (`export GOPATH=$HOME/go` — stays managed, `$HOME` intact, EVAL-01), imperative lines (`eval "$(...)"`, a function definition, `compinit`), a literal secret (`export API_TOKEN=sk-abc123` — excluded + reported), an already-dynamic secret (`export TOKEN=$(op read ...)` — committed verbatim, not reported), and — for the idempotency + out-of-block tests — a variant with the managed BEGIN/END block already present plus trailing installer-appended lines (`# added by nvm` + `export NVM_DIR=...`). Fixtures live under the test package following the existing fixture precedent; tests that require `zsh` follow the `LookPath`-guarded `zsh -f` skip pattern (`introspect_test.go` / `corpus_test.go`).
- **D-15: The store is injected into `CLI` at the composition root; `core/cli` never imports the concrete store/provider.** `core/cmd/zsh-pro/main.go` already constructs the store (`store.New(dir, provider, kc)`, currently held as `_, _ = s, err` reserving it for the store-backed verbs) and injects the provider into `cli.New(provider)`. Phase 6 threads the store into the CLI via a minimal store-facing interface declared in `core/cli` and satisfied by `*store.Store` (the same injection pattern Phase 5 D-19 establishes — Phase 6 reuses or extends whatever Phase 5 lands, NOT a competing injection path). A store-init error stays non-fatal for `analyze` (which needs no store) and surfaces only when `ingest` (or another store-backed verb) runs — matching main.go's existing comment. The interface should be narrow (only what ingest needs: `Init`, `Commit`; plus whatever Phase 5's verbs added). `core/cli`, `core/ir`, and `core/store` continue to NOT import `core/shell/zsh` (SPEC acceptance criterion).
- **D-16: If Phase 5 has landed its store-injection seam by Phase 6 plan time, Phase 6 EXTENDS it rather than defining a second one.** Phase 5 D-19 threads the store into `cli.New` for `list`/`status`/`checkout`. Phase 6's `ingest` needs the same store injection; the plan reconciles against Phase 5's actual `cli.New` signature / store interface (the same reconciliation-gate discipline as D-07) and adds `Init`/`Commit` to whatever narrow interface Phase 5 declared, rather than introducing a parallel wiring path.

### Claude's Discretion

- The exact human-mode summary wording/labels and the `--json` envelope shape (dedicated DTO+renderer vs inline struct, D-04 / OQ-06-03) — provided the managed count, master-block line count, withheld list, and out-of-block warning are all present and no secret value / zsh text / store type reaches the wire.
- The exact seam by which Phase 6 reads Phase 5's marker constants for the out-of-block scan (D-12 / OQ-06-04) — provided the marker text has a single source of truth (the Phase 5 installer package) and `core/cli` holds no zsh/marker text if it crosses the seam.
- Whether the out-of-block detector co-locates with the Phase 5 installer (has the markers + the `~/.zshrc` read path) or in the ingest orchestration reading a marker constant (D-12) — provided it is read-only and never clobbers out-of-block content.

- The commit message text for the `main` baseline (D-10) and commit granularity within the phase (GSD `gsd-sdk query commit` flow).

<specifics>
## Specific Ideas

- **Zero silently-dropped lines is the load-bearing ingest invariant** (SPEC Requirement 1): every source statement is either a committed managed entry OR routed verbatim to the master block. The `managed_entries + master_block_lines` accounting (over non-blank, non-comment statements) is computed, surfaced (D-03), and pinned by test — a dropped imperative line is a zero-residue violation by construction (ING-02).
- **`EffectiveManaged()` is the ONE partition predicate** — the store view (managed) and the master block (imperative) split the source on the same boolean `ir.Regenerate` already gates on (D-05). Phase 6 adds no classification; the precision-over-recall gate stays in `core/ir/route.go`.
- **The secret literal must never reach the committed tree** (SPEC Requirement 2): Phase 3's `excludeSecrets` already guarantees this (literal cleared from BOTH `Text` and `Value`, replaced by a `SecretRef` placeholder, `core/store/secret.go:136-153`); Phase 6 only SURFACES the `WithheldReport` and never prints a value. Grep of the committed blobs returns nothing — the phase's falsifiable secret property.
- **Idempotency is byte-exact and reuses Phase 5's rewrite** (SPEC Requirement 3): a second ingest on an unchanged file leaves the managed BEGIN/END region byte-identical (`diff` empty, `grep -c` BEGIN == 1) and content outside the markers unchanged. Phase 6 does NOT write a second block writer — it drives Phase 5's byte-exact rewrite.
- **Out-of-block content is detected, warned, and left untouched** (SPEC Requirement 4): read-only surfacing (D-11) — never clobber/reorder; ingest exits without error (a warning, not a failure).
- **The Phase 2 oracle is the end-to-end correctness pin** (SPEC Requirement 5 / ING-01): the same oracle that guards synthetic IR fixtures now runs against a real ingested `~/.zshrc`, closing the ingest loop.
- **Forward references are reconciled at plan time, not assumed:** Phase 5 is planned but not yet executed (no markers/installer on disk), so the master-block routing target (D-07) and store-injection seam (D-16) are plan-time reconciliation gates against Phase 5's actual landed code — the same discipline Phase 5 used against Phase 4's `emit.go`.
