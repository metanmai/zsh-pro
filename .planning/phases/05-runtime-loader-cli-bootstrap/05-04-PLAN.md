<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| interactive shell -> explicit runtime verb | User shell options such as ERR_EXIT and ERR_RETURN can turn an ordinary helper failure into terminal exit. |
| loader -> emitter and validator subprocesses | A broken or slow executable can block mutation and the interactive prompt. |
| active profile -> target profile | Live shell state crosses ownership boundaries and stale state is observable after a switch. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-04-01 | Denial of Service | emit and zsh validation commands | high | mitigate | Portable watchdog deadline, child reaping, and sleeping-shim wall-time tests. |
| T-05-04-02 | Denial of Service | ERR_EXIT/ERR_RETURN public verbs | high | mitigate | Conditional internal failures, always cleanup, explicit error state, and zero-return interactive failure contract. |
| T-05-04-03 | Tampering | active-to-target transition | high | mitigate | One complete Diff-rendered transition plus real Store/emitter A-only ownership test. |
| T-05-04-04 | Information Disclosure | staged emitted source | medium | mitigate | Exclusive restrictive staging, unconditional removal, history protection, and xtrace restoration. |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package-manager installation occurs. |
</threat_model>
