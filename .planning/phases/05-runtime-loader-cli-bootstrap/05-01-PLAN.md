<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| binary stdout -> sourced verb `eval` | The verb `eval`s the binary's emitted apply/deactivate code into the LIVE shell — untrusted-shaped code crosses into execution here (mitigated by the `zsh -n` gate in Plan 05-02). |
| profile/var/alias/function name -> `typeset -g` slot target | A derived slot name embeds user-controlled profile/var names; an unsanitized name is an invalid `typeset` target AND a command-substitution injection vector. |
| provider seam -> core/cli | The loader zsh text crosses the `HookScript()` seam; core/cli must hold no zsh text (layering + reduces the surface where zsh syntax originates). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Elevation of Privilege / Tampering | slot-name derivation in `zp_capture_env`/shadow slots (`hook.go`) | mitigate | Sanitize `${name//[^A-Za-z0-9_]/_}` BEFORE any `typeset -g`/`${(P)}` on a derived name (D-02/C8, verified E16 that `$(...)` in a raw name EXECUTES). Task 2 acceptance greps the loader for the sanitize expression on every derived-name path. |
| T-05-02 | Tampering | `zp_restore_env` reversing a hand-changed value | mitigate | Drift guard: reverse only if `[[ "${(P)+var}" == "1" && "${(P)var}" == "$applied" ]]` (D-01/C6). Task 2 live_terminal_test covers the reverse-only-if-unchanged behavior. |
| T-05-03 | Denial of Service | env unset-vs-empty mis-encoding (`${(P)+var}` vs `-z`) leaving residue | mitigate | Use `[[ "${(P)+var}" == "1" ]]` (operand holds the NAME, C6) + `${slot+x}` shadow set-test (C7), never `-z`/`-n` (which silently drop empty priors). Task 2 acceptance greps for the correct forms. |
| T-05-04 | Information disclosure | secret `SecretRef` deref leaking into emitted code/shell history | accept (Phase 5 scope) | Phase 5 only drives the existing `store.KeychainDriver` seam if emitted code carries an unresolved `SecretRef` (OQ-05-02); end-to-end PROF-03 is Phase 6. Residual: no NEW secret path is introduced here; the emit path (Phase 4) owns quoting. |
| T-05-05 | Tampering | zsh text leaking into `core/cli` (bypassing the single-emit-path invariant) | mitigate | Loader const lives only in `core/shell/zsh/hook.go`, reached via `HookScript()` (D-20). Task 2/3 acceptance greps that `core/cli` holds no zsh text. |
| T-05-SC | Tampering | npm/pip/cargo installs | mitigate | No new dependencies in this plan (loader is an embedded `const`; `hyperfine`/`zsh -n` are dev/CI tools, not Go modules — SPEC constraint). No package-manager install task exists; no Package Legitimacy Gate required. |

No HIGH-severity threat is left uncovered. T-05-04 is an accepted residual scoped out to Phase 6 (no new secret path introduced here).
