Proven installer algorithm (RESEARCH sub-area (c) D1 / C9 — byte-identical POC):
```
begin = "# >>> zsh-pro >>>"; end = "# <<< zsh-pro <<<"
render() -> deterministic canonical block (begin..end inclusive)
if !contains(cur, begin):
    if cur == "": return block + "\n"                       # create
    ensure trailing \n; return cur + "\n" + block + "\n"    # append at EOF
else:
    emit bytes before first region verbatim
    emit fresh block ONCE at first region position
    DROP every subsequent region (dup collapse)
    preserve all bytes between/after regions verbatim
```

Proven guard-order stub (RESEARCH sub-area (d) / C10/C12):
```
# >>> zsh-pro >>>
[[ -n "$ZSHPRO_DISABLE" ]] && return 0                                  # 1. full no-op escape hatch
[[ -r "$HOME/.zsh-pro/loader.zsh" ]] && source "$HOME/.zsh-pro/loader.zsh"  # 2. readability guard, then source cached loader
# <<< zsh-pro <<<
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `zsh-pro install` -> `~/.zshrc` | The installer rewrites the user's login file; clobbering content outside the markers is destructive data loss. |
| cached loader file -> every shell start | The stub sources a cached loader file on every interactive start; a tampered/writable cached file executes on each start. |
| emitted code -> verb `eval` | The verb `eval`s emitted apply/deactivate code into the live shell; unvalidated code is arbitrary execution. |
| broken/absent binary/loader -> `.zshrc` startup | A failure that propagates a non-zero exit or hangs could lock the user out of a working shell. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-06 | Tampering (destructive) | `.zshrc` installer clobbering user content outside markers | mitigate | Byte-exact find-region-then-replace preserves outside-marker bytes verbatim; atomic temp-file + `os.Rename` (D-10/C9). Task 1 acceptance: bytes outside markers unchanged (diff empty); user content survives; atomic rename. |
| T-05-07 | Denial of Service | broken/slow/absent `zsh-pro` or malformed loader aborting `.zshrc` (lockout) | mitigate | Fail-open stub: `ZSHPRO_DISABLE=1` full no-op -> `[[ -r <cached> ]]` readability -> source; no stub path emits a shell-aborting non-zero exit (D-11/D-14/C10/C12). Task 2 acceptance: absent binary reaches prompt; `ZSHPRO_DISABLE=1` defines no verbs. |
| T-05-08 | Tampering / Code injection | `eval` of un-validated emitted code into the live shell | mitigate | `zsh -n` the ENTIRE captured block before `eval`; refuse-all-on-failure (atomic, no half-apply); last-good state preserved (D-15/D-16/C11/C13).
