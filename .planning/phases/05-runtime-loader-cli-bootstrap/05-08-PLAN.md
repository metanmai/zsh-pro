<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| persisted profile and resolver -> runtime emitter | Profile values and resolved secrets become emitted shell source. |
| runtime emitter -> sourced zsh transaction | Generated source changes the caller shell's functions, variables, and exports. |
| inherited environment -> loader state detection | A nested shell can inherit exported profile metadata without having performed an activation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-08-01 | Tampering | `runtimeEmitter.Emit` active-profile inference and reverse payload | high | mitigate | Emit `apply` from the requested target only, pair `Diff(nil, target)` with `Diff(&targetManifest, nil)`, and retain the target reverse function before testing explicit main transitions. |
| T-05-08-02 | Information disclosure | active secret profile reverse path | high | mitigate | Reverse with the active target's retained in-shell `zp_deactivate` function before any next-target payload redefines it, and test resolver loss so no old SecretRef is re-read while its export is removed. |
| T-05-08-03 | Spoofing | inherited `ZSHPRO_PROFILE` | medium | mitigate | Require a non-exported marker set only after successful loader evaluation before treating state as active. |
| T-05-08-04 | Denial of service | resolver outage during switch/deactivate | high | mitigate | Resolve only a newly requested target; deactivation and old-profile cleanup invoke the retained reverse with no resolver dependency and receive stateful failure tests. |
| T-05-SC | Tampering | npm/pip/cargo installs | high | accept | This plan has no package-manager install task or dependency change; the supply-chain install boundary is not opened. |
</threat_model>
