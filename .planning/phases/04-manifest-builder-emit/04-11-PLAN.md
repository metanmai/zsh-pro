  <name>Task 2: Order commit effects and roll back backend state on every late failure</name>
  <files>core/store/errors.go, core/store/store.go, core/store/git.go, core/store/store_test.go, core/store/secret_test.go</files>
  <read_first>

    - core/store/secret_test.go (fake backend patterns and secret-leak assertions)
    - core/store/errors.go (typed-error conventions and redaction boundary)
  </read_first>
  <behavior>
    - RED: if the second of multiple backend Store calls fails, all earlier writes are restored exactly and the branch SHA is unchanged.
    - RED: if update-ref fails after all backend writes, every key is restored exactly and the branch SHA is unchanged.
    - RED: rollback restores a previously absent key with Delete and a previously present key, including present-empty, with Store of its exact old bytes.
    - RED: a snapshot Retrieve operational failure aborts before any write or branch move.
    - RED: rollback failure returns ErrSecretRollback without secret data or raw backend/git text; the original branch still does not move.
    - RED: a Store that mutates then returns an error is rollback-eligible and restores its exact prior state; Delete returning not-found while restoring prior absence is idempotent success.
    - RED: update-ref fail-before-effect leaves the old/absent ref, fail-after-effect is detected by re-read and compensated, and a concurrent ref move is preserved and returned as a typed redacted conflict.
  </behavior>
  <action>
    Refactor Commit into the following explicit order: validate; prepare and redact; marshal/regenerate; create blobs/tree/commit object without moving the ref; retrieve and snapshot each unique pending key; apply pending backend writes; update-ref last. Blob and commit objects may remain unreachable after failure, but externally visible branch and backend state must not change.

    Before invoking each Store, mark that key rollback-eligible; a backend is allowed to mutate and then return an error, so the current key as well as all earlier keys must be restored in reverse mutation order. Restore an old present value with Store and old absence with Delete. Treat a typed not-found result from Delete while restoring absence as idempotent success. Continue rollback across keys even after one restoration error, then return the redacted typed ErrSecretRollback when any rollback step failed; otherwise return the original typed error. Do not return a successful report on failure. Snapshot all keys before the first mutation so a lookup failure is side-effect free.

    Replace unconditional update-ref with compare-and-swap: pass the observed old SHA for an existing branch and the all-zero old object ID for a new branch. If update-ref reports failure or timeout, re-read the target ref before classifying the outcome. If it is still old/absent, the ref had no effect. If it equals the newly created commit, compensate with a second CAS back to the old SHA or a CAS-guarded delete for a new ref, then verify the result. If it equals a third SHA, never overwrite concurrent work; roll back secrets and return a typed redacted ref-conflict/ambiguous error. If compensation or re-read cannot prove a safe state, return ErrSecretRollback or a dedicated typed ambiguous-ref error without raw git text or secret data.

    Add only per-instance, test-scoped update-ref and ref-read seams on Store/gitRunner that can model fail-before-effect, mutate-then-timeout, compensation failure, and concurrent movement; do not introduce mutable package-global state. The production default must directly call existing git plumbing, and every test instance must own its failure injection so parallel or later tests cannot inherit it.
  </action>
