### C1 — `${(P)+var}` set-test for a literal slot name
- **Claim:** `${(P)+var}==1` iff the parameter named by `$var` is SET (incl. empty), 0 if unset — used to test whether a literal-named slot is set.
- **What actually happened:** `zsh -f -c 'FOO=bar; print ${(P)+FOO}'` printed `0`, not `1`. `(P)` indirects through the VALUE of `FOO` (`bar`), testing a parameter literally named `bar` (which does not exist). The stated semantic is correct, but the reproduction recipe conflated `${(P)+FOO}` with `${+FOO}`.
- **Correct fact:** To set-test a LITERAL-named slot, use `${+FOO}` (no `(P)`): unset→0, set-including-empty→1. `(P)` is correct ONLY when the slot NAME is stored in another variable (`name=FOO; ${(P)+name}`). The `-n`-cannot-distinguish-unset-from-empty half is independently confirmed.
- **Action taken:** Replaced every `${(P)+literalName}` set-test in the shadow-restore / env-drift guard guidance with `${+name}` (no P) across 04-RESEARCH.md (Pitfall 4, Don't Hand-Roll, State-of-the-Art, appendix), 04-CONTEXT.md (D-12), 04-OPEN-QUESTIONS.md (OQ-8), and 04-SPEC.md. Retained `(P)` only for the env path where the operand IS a var holding the name (C21, confirmed correct there).
