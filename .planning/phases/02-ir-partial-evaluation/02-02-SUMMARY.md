# Phase 2 Plan 02: Regeneration + Round-Trip Oracle Summary

**A narrow `shell.Regenerator` seam with the declarative templater in `core/shell/zsh`, the whole-file `ir.Regenerate` that emits a Profile in source order (templated declaratives + verbatim everything-else), and the byte-identical round-trip oracle that proves behavior-equivalence under sandboxed `zsh -f` — dynamic values stay late-bound, never resolved.**

## Accomplishments
- `shell.Regenerator` interface added and composed into `shell.Provider` (the single place forward zsh syntax is generated this phase). `zsh.Provider.Regenerate` rebuilds each declarative Kind from structured fields — `export NAME=VALUE` / `NAME=VALUE`, `alias NAME=VALUE`, `setopt/unsetopt NAME...`, the full `name(){...}` func span — emitting the captured `Value` VERBATIM so `$HOME/go` stays `$HOME/go` (never `%q`-quoted, never resolved — D-05/EVAL-01/Pitfall 3). The `default` case returns verbatim `Text`, making the seam total (#3).
- `ir.Regenerate(model.Profile, shell.Regenerator) []byte` emits the whole file in stored (source) order (D-09): managed entries (after `EffectiveManaged`, Override wins — D-07) go through the Regenerator; imperative / Opaque / forced-unmanaged entries are emitted verbatim from `Text` (D-01/D-10). `core/ir` generates NO zsh syntax and does NO home resolution — all codegen is delegated (Pitfall 5 / EVAL-01).
- The round-trip oracle (`TestRegenRoundTrip`, external pkg `ir_test`) parses → Build → Regenerate a fixture covering all 5 declarative classes (static env, dynamic env, dynamic PATH, alias, setopt option, function), sources the original and regenerated `.zsh` each under sandboxed `zsh -f`, and asserts `model.IdentitySet` equality across Aliases/Functions/Env/Options/Path (D-08). It also pins EVAL-01 SC3: the regenerated bytes still carry the literal `$HOME/go` and `$HOME/bin:$PATH`, and `GOPATH` resolves identically in both snapshots.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Parser did not capture setopt/unsetopt option names into Block.Names**
- **Found during:** Task 1 (probing how `setopt EXTENDED_GLOB` parses before writing the templater test).
- **Issue:** Plan 02-01's `routeManaged` admits `setopt/unsetopt` only when `len(b.Names) > 0`, and its `build_test.go` table assumes `setopt EXTENDED_GLOB` → `Names: ["EXTENDED_GLOB"]`. But the real parser's `describe` `default` case set `Kind=KindCommand` + `CmdName="setopt"` and left `Names` empty — so every real `setopt` routed IMPERATIVE and the options class would never reach the templater, defeating this plan's must-have ("setopt-unsetopt options rebuilt from their structured fields, not echoed from Text") and leaving Task 3's oracle unable to exercise the options class as templated.
- **Fix:** Added a `case "setopt", "unsetopt"` in `parse.go`'s `describe` that captures each non-flag option-name arg (via the existing `wordLitPrefix`, skipping `-flags`) into `b.Names`. This keeps all zsh-syntax knowledge in `core/shell/zsh`.
- **Files modified:** `core/shell/zsh/parse.go`
- **Commit:** `092f391`

**2. [Rule 3 - Blocking] Extending shell.Provider broke analyze_test mocks**
- **Found during:** Task 1 commit (pre-commit golangci-lint typecheck).
- **Issue:** Adding `Regenerator` to the composite `shell.Provider` meant `mockProvider`/`errProvider` (used with `analyze.New(shell.Provider)`) no longer satisfied the interface (missing `Regenerate`), failing compilation of `core/analyze` tests.
- **Fix:** Added a trivial `func (m mockProvider) Regenerate(e model.Entry) string { return e.Text }` to `mockProvider` (`errProvider` embeds it, so it inherits the method). The analyzer itself does not use regeneration; this only keeps the test double satisfiable.
- **Files modified:** `core/analyze/analyze_test.go`
- **Commit:** `092f391`
