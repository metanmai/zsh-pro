<objective>
Build the IR construction path: the `model.Profile`/`model.Entry` types, an additive parser enhancement that captures each entry's verbatim value + a static/dynamic flag, the `core/ir.Build` orchestrator that turns `[]model.Block` into an ordered `Profile`, and the declarative/imperative routing gate.

Purpose: This is the spine the rest of the v2.0 milestone serializes (Ph3 store, Ph4 manifest). It must classify each statement declarative-vs-imperative (the switchability gate, ING-02) and tag values static-vs-dynamic for portability (EVAL-01) — performing NO execution of user config.
Output: `core/model/profile.go` (new types), additive fields on `core/model/block.go`, value/dynamic capture in `core/shell/zsh/parse.go`, the new `core/ir` package (`build.go`, `route.go`), and pure-Go tests pinning routing, override, and dynamic detection. Regeneration + the round-trip oracle are Plan 02-02.

## Design forks resolved in this plan

- **Value-capture fork → Approach A (RESEARCH-recommended).** `model.Block` has no value/body field today (`core/model/block.go:27-37`). Add agnostic scalar fields `Value string` and `Dynamic bool`, populated at parse time in `describe()` — the only place with the mvdan/sh AST. Keeps `core/model` dependency-free and `core/ir` shell-free; AST-accurate (a regex over `Block.Text` mishandles single-quoted `$HOME` and escaped `\$`). Approaches B (re-parse in `core/ir` — impossible, the interface returns no AST) and C (string-split `Block.Text` — fragile vs quoting) are rejected.
- **Static/dynamic detection placement → `core/shell/zsh` (the AST tier).** Detection runs over the `*syntax.Word` at parse time and lands as the agnostic `Block.Dynamic bool`, so `core/ir` never touches the AST.
</objective>
