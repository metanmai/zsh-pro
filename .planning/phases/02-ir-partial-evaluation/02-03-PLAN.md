<objective>
Close the UAT round-trip gap: a single-name ARRAY assignment (`plugins=(git zsh-autosuggestions zsh-syntax-highlighting)`, single-line OR multi-line) currently regenerates as a bare `plugins=`, silently dropping the array value and breaking oh-my-zsh plugin load. Detect array assignments at parse time, route them imperative (verbatim Text), and pin the fix with an oracle fixture.

Purpose: This is an ING-01 round-trip-fidelity defect of the SAME class as the already-fixed BL-02 (multi-name) / WR-01 (`+=`) / WR-02 (alias `-g`): a shape the scalar templater cannot faithfully reproduce. The established D-04/D-06 remedy is "manage only faithfully-reproducible shapes; route the rest imperative-verbatim." Array assignments (`plugins=(...)`, `fpath=(...)`, `path=(...)`, any `arr=(...)`) are near-universal in real configs, so this is silent config corruption that must be closed before the env-manager round-trip can be trusted.
Output: an additive `model.Block.Array` flag, array detection in `core/shell/zsh/parse.go`, an array guard in `core/ir/route.go`'s `routeManaged`, a defensive empty-Value guard in `core/shell/zsh/regen.go`, and oracle coverage in `core/ir/roundtrip_test.go`.

## Why route imperative (not template the array)

The scalar templater in `regen.go` emits `name=VALUE` from a single captured scalar `Value` string. mvdan/sh models an array assignment as `a.Array` (`*ArrayExpr`) with `a.Value == nil`, so there is no scalar `Value` to template and the parser captures nothing — `b.Value` stays empty. Rather than teach the templater a second array codegen path (new surface, new corruption risk, must preserve multi-line formatting and any in-array dynamic values), this plan follows the proven hardening principle already encoded in `routeManaged`: a verbatim round-trip is always safe; a lossy template is not. Array assignments route imperative and are emitted as their verbatim `Text` (full `(...)` span, multi-line included), exactly like multi-name / `+=` / flagged shapes.
